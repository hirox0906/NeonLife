# NEON LIFE OVERDRIVE

ネオン風の演出で複数のセル・オートマトンを観察できる、ブラウザ向けシミュレーターです。依存ライブラリやビルド処理はなく、静的ファイルだけで動作します。

## 収録モデル

| モデル | 概要 | 初期パラメータ |
| --- | --- | --- |
| Conway's Life | 標準的なライフゲーム | B3/S23 |
| Wa-Tor | 魚の繁殖とサメの捕食・餓死 | 魚繁殖 6、サメ繁殖 10、体力 7、捕食回復 5 |
| HighLife | 自己複製パターンを持つLife系ルール | B36/S23 |
| Seeds | 生存セルが毎世代消滅する拡散的なルール | B2/S |
| Brian's Brain | 発火、休止、死の3状態モデル | 発火近傍 2、休止 1ターン |
| Rock Paper Scissors | グー、パー、チョキによる循環侵食 | 侵食近傍 3、突然変異率 0% |

Life系モデルの `BIRTH (B)` と `SURVIVE (S)` には、適用する近傍数を続けて入力します。例えば `B=36` は「近傍が3個または6個なら誕生」を意味します。

## 共通設定

| 画面上の変数 | 範囲 | 初期値 | 説明 |
| --- | ---: | ---: | --- |
| `SPEED` | 1〜30 | 12 | 1秒あたりの世代更新回数の目安。値を上げるほど進行が速くなります。 |
| `CELL` | 4〜14 | 6 | 1セルの表示サイズ（px）。値を小さくすると盤面の行列数が増え、変更前の盤面は中央を基準に可能な範囲で保持されます。 |
| `CHAOS` | 8〜45% | 24% | `RANDOM BURST`の初期配置に使う値。Life系、Wa-Tor、Brian's Brainではセルを配置する確率です。Rock Paper Scissorsでは種族のまとまり具合を決め、値が低いほど大きな領域、高いほど細かなランダム模様になりやすくなります。 |

盤面の上下端と左右端はつながっています。Conway's Life、HighLife、Seeds、Brian's Brain、Rock Paper Scissorsは周囲8セル（ムーア近傍）を参照し、Wa-Torの移動と捕食は上下左右4セルを参照します。

## ルール別の変数と挙動

### Conway's Life

| 変数 | 入力 | 初期値 | 説明 |
| --- | --- | --- | --- |
| `BIRTH (B)` | 0〜8の数字列 | `3` | 死セルが生セルになる近傍数。 |
| `SURVIVE (S)` | 0〜8の数字列 | `23` | 生セルが次世代も生存する近傍数。 |

各世代は盤面全体を同時に更新します。死セルは生きた近傍が3個のとき誕生し、生セルは近傍が2個または3個のときだけ生存します。それ以外は死セルになります。入力した数字は重複を除いて昇順に解釈されます。

### HighLife

変数の形式はConway's Lifeと同じで、初期値は `B36/S23` です。生存条件はConwayと同じですが、死セルは近傍が3個に加えて6個の場合にも誕生します。この追加条件により、適切な初期パターンから自己複製に似た振る舞いが現れます。

### Seeds

変数の形式はConway's Lifeと同じで、初期値は `B2/S` です。`SURVIVE (S)` が空なので、生セルは近傍数に関係なく次世代で必ず死セルになります。死セルは生きた近傍がちょうど2個のときだけ誕生するため、火花が広がるような拡散的な模様になります。

### Brian's Brain

| 変数 | 範囲 | 初期値 | 説明 |
| --- | ---: | ---: | --- |
| `BIRTH NEIGHBORS` | 1〜8 | 2 | 死セルが発火するために必要な、周囲の発火セル数。ちょうどこの個数のときだけ発火します。 |
| `REST TURNS` | 1〜8 | 1 | 発火後に休止状態を維持する世代数。 |

セルは「死 → 発火 → 休止 → 死」の順に遷移します。発火セルは次世代で必ず休止状態になり、指定ターンの間は再発火できません。死セルだけが `BIRTH NEIGHBORS` の条件を満たしたときに発火します。`RANDOM BURST`では発火セルだけをランダムに配置します。統計表示 `FIRE/REST` は発火セル数と休止セル数です。

### Wa-Tor

| 変数 | 範囲 | 初期値 | 説明 |
| --- | ---: | ---: | --- |
| `FISH BREED` | 1〜30 | 6 | 魚が繁殖可能になる年齢（世代数）。 |
| `SHARK BREED` | 1〜30 | 10 | サメが繁殖可能になる年齢（世代数）。 |
| `SHARK ENERGY` | 1〜30 | 7 | 新しく配置されたサメと、繁殖時に元の位置へ残るサメの体力。 |
| `FOOD ENERGY` | 1〜30 | 5 | サメが魚を1匹食べたときに回復する体力。 |

各世代で個体の処理順をランダム化します。魚は上下左右の空きセルから1つを選んで移動し、繁殖年齢に達していれば移動元にも魚を残して両方の年齢を0に戻します。空きがない場合は移動せず、年齢だけが増えます。

サメは隣接する魚を最優先で選び、魚がいなければ空きセルへ移動します。毎世代体力を1消費し、魚を食べた場合は `FOOD ENERGY` を加算します。計算後の体力が0以下なら餓死します。繁殖年齢に達して移動できた場合は移動元にもサメを残します。`RANDOM BURST`で配置される個体は約78%が魚、約22%がサメです。統計表示 `FISH/SHARK` は魚とサメの個体数です。

### Rock Paper Scissors

| 変数 | 範囲 | 初期値 | 説明 |
| --- | ---: | ---: | --- |
| `TAKEOVER` | 1〜8 | 3 | セルが捕食側の種族へ変化するために必要な、周囲の捕食側セル数。指定値以上で侵食されます。 |
| `MUTATION %` | 0〜10% | 0% | 各世代で各セルがランダムな種族へ変化する確率。0%なら突然変異しません。 |

優劣は「パーがグーを侵食、チョキがパーを侵食、グーがチョキを侵食」の循環です。各セルは周囲8セルにいる捕食側の数を数え、`TAKEOVER` 以上ならその種族へ変化します。盤面全体は同時に更新されるため、波や渦のような境界が生まれます。突然変異の判定は侵食判定の後に行われ、発生時はグー・パー・チョキのいずれかへランダムに変化します。空セルは自動では種族に変化しません。統計表示 `R/P/S` はグー、パー、チョキのセル数です。

## 操作

- `MODEL`: シミュレーションモデルを変更
- `BRUSH`: クリックまたはドラッグで配置するセル／種族を変更
- 右ドラッグ: セルを消去
- `RUN`: 再生／一時停止
- `STEP`: 一時停止して1世代だけ進める
- `RANDOM BURST`: 現在のモデルで盤面をランダム生成
- `CLEAR`: 盤面を消去
- `RESET SETTINGS`: モデル固有パラメータとSPEED、CELL、CHAOSを初期値へ戻す
- `Space`: 再生／一時停止
- `R`: ランダム生成
- `C`: 盤面を消去

`RESET SETTINGS`は盤面や選択中のモデルを変更しません。

## ローカルで実行する

JavaScript Modulesを使用しているため、ファイルを直接開かずローカルサーバー経由で確認してください。

```bash
python -m http.server 8000
```

起動後、ブラウザで `http://localhost:8000/` を開きます。

## GitHub Pagesで公開する

1. このフォルダーのファイルをGitHubリポジトリのルートへ追加します。
2. GitHubのリポジトリ画面から **Settings → Pages** を開きます。
3. **Build and deployment** のSourceで **Deploy from a branch** を選択します。
4. 公開ブランチを `main`、フォルダーを `/(root)` にして保存します。
5. デプロイ完了後、表示されたPagesのURLへアクセスします。

詳しい手順は[GitHub公式ドキュメント](https://docs.github.com/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)を参照してください。
